# Информационная система риэлторского агентства «Ключевой выбор»

Работающее учебное приложение на Python 3.12+, Flask, SQLAlchemy 2, Jinja2 и SQLite. Серверная часть интегрирована с исходной адаптивной версткой. Главный источник предметных требований — «Практическая работа №1.docx» и критическое уточнение задания. Клиенты отправляют заявки и записываются на показы **без обязательной регистрации**. `Client` и `Agent` сохранены как отдельные предметные сущности; `User` отвечает за вход.

## Запуск с чистого окружения в Windows PowerShell

Откройте терминал в папке проекта. Python должен быть версии 3.12 или выше.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -c "from pathlib import Path; import secrets; p=Path('.env'); p.write_text(p.read_text().replace('replace-with-a-random-secret', secrets.token_hex(32)))"
flask --app run.py db upgrade
flask --app run.py seed-demo
python run.py
```

Откройте <http://127.0.0.1:5000>. Если активация виртуального окружения недоступна, используйте `.\.venv\Scripts\python.exe` вместо `python`, а вместо `flask` — `.\.venv\Scripts\python.exe -m flask`. Изменять системные политики для запуска не требуется.

В подготовленной рабочей копии `.env` уже создан со случайным локальным ключом, база и демо-данные уже подготовлены. Архив для передачи не содержит `.env`, БД и виртуального окружения: примените команды выше после распаковки.

## Демо-аккаунты

| Роль | Email | Пароль только для development |
| --- | --- | --- |
| ADMIN | admin@example.local | DemoPass123! |
| REALTOR | realtor@example.local | DemoPass123! |
| CLIENT | client@example.local | DemoPass123! |

`flask seed-demo` можно запускать повторно: шесть исходных карточек имеют неизменяемые `demo_key`, аккаунты определяются по email. Команда не перезаписывает существующие пароли и объекты. В `APP_ENV=production` демо-seed запрещен. Реальные секреты и учетные данные в исходниках не хранятся. Демонстрационные адреса `example.local` поддержаны специально; другие email проверяются валидатором.

Создание собственного администратора:

```powershell
flask --app run.py create-admin
```

Команда запросит ФИО, телефон, email и пароль с подтверждением; пароль вводится скрыто. Сотрудников также можно создавать через `/admin/users/new` после входа администратором.

## Архитектура

```text
app/
  __init__.py                 application factory, обработчики ошибок
  extensions.py              DB, LoginManager, CSRFProtect, Migrate
  cli.py                     seed-demo и create-admin
  models/__init__.py          семь предметных моделей, User, Favorite
  forms/__init__.py           формы и серверная валидация
  routes/
    main.py                  главная, публичные заявки, мои записи
    auth.py                  вход, регистрация, профиль, пароль
    catalog.py               каталог, карточка, избранное
    dashboard.py             операции риэлтора
    admin.py                 учетные записи сотрудников
  services/
    access.py                роли и ограничения доступа
    workflows.py             запись клиента, показы, сделки
    uploads.py               проверка и сохранение фотографий
  templates/
    base.html                общие header/footer, CSS/JS, сообщения
    index.html, catalog.html, property.html
    auth/, dashboard/, errors/, partials/
  static/
    css/styles.css           исходный CSS с дополнениями
    js/script.js             меню, fetch избранного, галерея, preview
    uploads/properties/      файлы с UUID
migrations/                  версионируемая начальная миграция
tests/                       функциональные тесты и проверки доступа
original/                    неизмененная исходная frontend-верстка
docs/                        схема БД, маршруты, итоговый отчет, проверки
config.py, run.py, requirements.txt, pytest.ini, .env.example
```

Использована [application factory Flask](https://flask.palletsprojects.com/en/stable/patterns/appfactories/) с Blueprints. [CSRFProtect](https://flask-wtf.readthedocs.io/en/1.2.x/csrf/) включен глобально. Все операции изменения выполняются POST, формы WTForms валидируют значения и списки допустимых ID. Код не использует React, SPA, JWT, очереди или микросервисы.

Исходные классы CSS, сетки, карточки, шапка, подвал, иллюстрации и темная боковая панель сохранены. Фильтрация, сортировка, формы и статистика перенесены на сервер. Изначальные нарисованные CSS иллюстрации остаются до загрузки реальных фотографий. На мобильном экране меню сотрудника теперь доступно, хотя исходный CSS его полностью скрывал.

## Модель данных и права

Подробная схема, атрибуты, ограничения и связи описаны в [docs/DATABASE.md](docs/DATABASE.md).

| Пользователь | Доступ |
| --- | --- |
| Посетитель без аккаунта | Каталог, поиск, фильтры, фото, контакты, заявка, запись на показ, свои записи текущего браузера |
| CLIENT | Публичные функции, профиль и пароль, собственные заявки/показы, избранное в БД |
| REALTOR | Свои объекты и фотографии, связанные клиенты, свои заявки/показы/сделки; свободные заявки можно взять в работу |
| ADMIN | Все рабочие записи, создание сотрудников, роли ADMIN/REALTOR, блокировка/разблокировка аккаунтов |

Публичная регистрация создает только CLIENT. Администратор не может заблокировать себя или снять собственную роль. Клиентский аккаунт не превращается в сотрудника через форму редактирования сотрудника. Заблокированный пользователь теряет доступ даже с ранее открытой сессией.

У гостя создается предметная запись `Client`, идентификатор хранится в подписанной сессии браузера. Телефон или email не используются как доказательство личности: другой посетитель с теми же контактами не получает чужую историю. Регистрация из этого же браузера привязывает текущую гостевую карточку к новому аккаунту. При обычном входе в уже существующий аккаунт гостевая история автоматически не объединяется. После удаления cookies гостевые записи остаются у агентства, но посетитель теряет доступ к ним. Между независимыми гостевыми сессиями возможны разные карточки одного человека; объединение клиентов не реализовано.

## Каталог и маршруты

Каталог отображает доступные и забронированные объекты; архив скрыт, проданные и сданные доступны по прямой ссылке без новой записи на показ. Серверные параметры:

```text
/catalog?q=Хамовники&deal=sale&type=flat&rooms=2&min_price=0&max_price=25000000&district=Хамовники&min_area=50&max_area=80&sort=price_asc&page=1
```

Типы: `flat`, `house`, `land`, `commercial`. `rooms=4` означает четыре и более. Сортировки: `newest`, `price_asc`, `price_desc`, `area_asc`, `area_desc`. По 12 записей на страницу. Некорректные фильтры возвращают 400 с ошибками; фильтры сохраняются в ссылках пагинации. Запрос строится через SQLAlchemy, специальные символы текстового поиска экранируются.

Все маршруты и HTTP-методы приведены в [docs/ROUTES.md](docs/ROUTES.md). Главные: `/`, `/catalog`, `/property/<id>`, `/request`, `/my-requests`, `/my-viewings`, `/login`, `/logout`, `/register`, `/profile`, `/favorites`, `/dashboard`, `/admin`.

## Правила сохранения данных

- Объект архивируется вместо физического удаления. Связанные показы, сделки и история сохраняются. Активные показы архивируемого объекта отменяются.
- Активный показ одного объекта одного клиента защищен уникальным `active_key`. После отмены или завершения новый показ разрешен.
- При заключении сделки продажи объект становится `sold`, аренды — `rented`. Сумма сделки независима от текущей цены объекта. Для объекта допускается одна заключенная сделка; заключенная сделка сохраняется как неизменяемая история. До заключения сделку можно редактировать и отменять.
- Фотографии проверяются Pillow по фактическому формату, повторно кодируются в JPEG без метаданных и сохраняются с UUID. Допустимы исходные JPEG, PNG и WebP; до 5 МБ и 20 Мп на фото, до 8 МБ на весь HTTP-запрос, не более 12 фото за отправку. Ошибочный файл отклоняет всю загрузку. Основное фото можно менять; при его удалении назначается другое.
- Внешние ключи основных записей используют RESTRICT; фотографии и избранное удаляются каскадно только с их родителем. Операции удаления учетных записей и клиентов не предоставляются.
- Все даты и время трактуются как местное время агентства в Москве. Локальный компьютер/сервер должен быть настроен на этот часовой пояс.

## Миграции, SQLite и MySQL

SQLite создается в `instance/realty.db`. Приложение не вызывает `create_all()` при старте; схема управляется миграциями.

```powershell
flask --app run.py db upgrade
flask --app run.py db current
flask --app run.py db check
# После собственного изменения моделей:
flask --app run.py db migrate -m "Описание изменения"
flask --app run.py db upgrade
```

`flask db init` нужен лишь для проекта без папки `migrations`. Здесь папка уже подготовлена, повторно выполнять init не надо.

Для MySQL создайте пустую БД с кодировкой `utf8mb4`, измените `.env` и примените миграции к новой БД:

```dotenv
DATABASE_URL=mysql+pymysql://user:password@localhost/realty_agency?charset=utf8mb4
```

PyMySQL включен в зависимости. Проверено построение DDL для MySQL; подключение к живому серверу MySQL в этой работе не проверялось. Автоматический перенос существующих данных SQLite в MySQL не реализован.

## Проверки и демонстрация

```powershell
python -m pytest -q
python -m pip check
```

Тесты используют отдельную временную БД. CSRF отключен только в `TestConfig`; отдельный тест включает защиту и проверяет обычные формы и AJAX. Проверяются роли, чужие записи, безопасный `next`, блокировка сессии, каталог, фильтрация/сортировка/пагинация, заявки гостей и аккаунтов, показы, избранное, CRUD, фото, сделки, миграции, повторный seed, шаблоны и внутренние ссылки. Подробные результаты — [docs/FINAL_REPORT.md](docs/FINAL_REPORT.md), [docs/pytest-output.txt](docs/pytest-output.txt).

Сценарий защиты:

1. Открыть главную и каталог, отфильтровать двухкомнатные квартиры по цене/площади/району.
2. Открыть карточку, заполнить контакты и записаться на показ без аккаунта.
3. Отправить заявку на подбор, открыть «Мои заявки» и «Мои показы».
4. Войти как REALTOR, увидеть новые записи, взять свободную заявку, открыть подбор по параметрам.
5. Назначить дату показа, затем записать результат.
6. Добавить клиента и объект, загрузить фотографии, проверить появление объекта в каталоге.
7. Создать сделку в подготовке, завершить ее; проверить статус объекта и показатели кабинета.
8. Войти как ADMIN, создать сотрудника, изменить роль, заблокировать/разблокировать аккаунт.
9. При желании зарегистрировать CLIENT и проверить избранное, профиль и историю аккаунта.

## Границы учебного проекта

Приложение запускается локально через встроенный Flask-сервер. Для публикации нужен отдельный production WSGI-сервер с HTTPS, надежным SECRET_KEY, `APP_ENV=production`, резервным копированием БД и файлов. Cookies в production помечаются Secure, а CSRF остается включенным. Восстановление пароля по email, подтверждение контактов, внешние уведомления, карты, выгрузка документов, аудит и rate limiting не включены в обязательную часть этой учебной системы. Контакты агентства и демо-объекты взяты из предоставленного макета и предназначены для демонстрации.
